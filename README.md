# DxRChartsQuest — Can a vision-language model reconstruct the data table of a VR chart?

Research project (OpenCIVAN). Team: **Sai Shreyas Venishetty**, **Yashwanth Karthikeya Settem**.

We build 3D charts with the **DxR** toolkit in Unity, run them on a **Meta Quest 2**, record what the user sees, and ask
a vision-language model (VLM) to write the chart's underlying data table as CSV. Because we built the charts from known
datasets, every answer can be scored value by value against the true table.

**Research questions**

1. **RQ1 — How well can a VLM reconstruct the table** of a chart it only sees through a VR headset recording?
2. **RQ2 — How can we retrieve the data more accurately?** (better frames, several frames, prompting, fine-tuning)

## Where we are (line chart, real Quest recording, 48 true values)

| Model | Input | Within 5 % | Within 2 % | Mean error |
|---|---|---|---|---|
| Qwen3-VL-8B, untrained (baseline study) | best single frame | 67–74 % | – | – |
| Run 1: Qwen3-VL-8B + LoRA | best single frame | 88 % | – | – |
| Qwen3.5-9B, untrained | 8-frame video | 50 % | 11 / 48 | 7.43 % |
| Run 3: Qwen3.5-9B + LoRA (1,000 clips, 640 px) | 8-frame video | 97.9 % | 35 / 48 | 1.68 % |
| **Run 4: Qwen3.5-9B + LoRA (2,000 clips, 800 px)** | 8-frame video | **100 %** | 19 / 48 | 2.38 % |

All LoRA training uses **only synthetic charts** generated by our scripts. The real Quest recordings are test inputs
only, and the true tables are read only by the scorer after the model has answered (details:
[docs/6_scoring_and_metrics.md](docs/6_scoring_and_metrics.md)).

## Repository map

| Folder | Contents |
|---|---|
| `ground_truth/` | the true tables of the 5 charts (CSV), used only for scoring |
| `vlm_eval/` | frame extraction, prompts (`prompts.md`), scoring (`score_tables.py`), prompt helpers (`run_local_vlm.py`), baseline study scripts |
| `finetune/` | runs 1–2: synthetic image dataset, LoRA training and evaluation for Qwen3-VL-8B |
| `finetune_video/` | runs 3–4: synthetic video dataset, LoRA training, evaluation, median voting |
| `notebooks/` | end-to-end notebooks for Colab (A100 / T4) and Kaggle (free T4) |
| `results/` | result tables, training info and the model's raw answers for runs 3 and 4 |
| `docs/` | step-by-step documentation |

Not stored in git (too large, see `.gitignore`): Quest videos, extracted frames, generated training data and trained
LoRA adapters. The adapters are kept in Google Drive (`dxr_lora/`).

## Quick start (run 4, line chart)

```bash
# on the Mac: turn recordings into 8-frame test clips and pack the project
python3 finetune_video/sample_real_videos.py ~/Desktop/quest_videos --charts line
zip -qr ~/Desktop/dxr_video_upload.zip finetune_video vlm_eval ground_truth real_clips frames.csv frames_all -x 'finetune_video/data*'
```

Then open `notebooks/Run4_line_colab.ipynb` in Colab (or `Run4_line_kaggle.ipynb` on Kaggle) and run the cells in
order; see [docs/7_compute_and_reproduce.md](docs/7_compute_and_reproduce.md).
